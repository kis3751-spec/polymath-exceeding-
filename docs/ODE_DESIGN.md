# Differential Equations 기본 설계 초안

Equation Solver 변경의 검증·미해결 정리와 `bde1e04` 브랜치 업로드를 먼저 완료한 뒤 작성한 설계입니다. 이 문서는 **다음 구현의 계약**이며 실행 가능한 ODE 계산기를 추가한 것은 아닙니다. 홈의 미분방정식 카드는 아직 준비 중입니다.

## 1. 첫 구현 범위

초기 Polymath 자료의 `spec_deq.md`에 따른 한 독립변수의 초기값 상미분방정식과 연립 ODE를 대상으로 합니다. 예를 들어 농도·시간 모델의 입력과 초기조건은 다음과 같습니다.

```text
# 첫 번째 구현의 권장 입력 예시
f1 = k*A
d(A)/d(t) = -f1
d(B)/d(t) = f1
A(0) = 10
B(0) = 0
t(0) = 0
t(f) = 5
```

`k=0.3`은 파라미터 카드에 등록합니다. Polymath 파일의 `k=0.3` 행은 ODE 모드에 한해 명시적인 보조식으로 가져올 수 있도록 설계합니다. Equation Solver의 `k=0.3`이 일반 방정식이라는 의미는 바꾸지 않습니다. 두 모드의 파서 진입점을 분리합니다.

초기조건이 없는 해의 자동 추측, 경계값 문제, DAE, PDE, 지연미분방정식, 확률미분방정식은 첫 범위에 포함하지 않습니다. ODE의 초기조건은 NLE의 Newton 시작 추측과 달리 실제 해 궤적을 정하므로 필요합니다.

## 2. 문법 계약

| 표기               | 의미                          | 검증                                                                        |
| ------------------ | ----------------------------- | --------------------------------------------------------------------------- |
| `d(A)/d(t) = -k*A` | 독립변수 t에 대한 A의 변화율  | 상태별 하나, 모든 행의 독립변수 일치                                        |
| `A' = -k*A`        | 위 식의 짧은 표기             | 범위에서 독립변수가 하나로 결정될 때만 허용                                 |
| `dA/dt = -k*A`     | Polymath 압축 표기 가져오기   | 이름 분리가 유일할 때만 허용, 편집기에 정규 표기 제안                       |
| `A(0)=10`          | 적분 시작점의 A 초기값        | Polymath의 0은 초기 슬롯. t 시작값이 2라면 A(t=2)=10이라는 뜻임을 UI에 표시 |
| `t(0)=0`, `t(f)=5` | 독립변수 시작·종료            | 유한 값, 시작과 종료가 다름                                                 |
| `t\|0:5`           | Polymath 범위 약식 가져오기   | 위 두 조건으로 정규화, 중복 범위는 거부                                     |
| `f1(t)=sin(t)`     | 독립변수만 사용하는 번호 함수 | 기존 단일변수 함수 순도 규칙 재사용                                         |
| `f2(A)=A^2`        | 상태 A에 대한 번호 함수       | A 이외 미지수 혼합 금지, 등록 파라미터 허용                                 |
| `f1=k*A*B`         | 여러 상태를 사용하는 혼합식   | 의존 DAG, 미정의·순환 참조 거부                                             |
| `r=k*A`            | Polymath 보조식 가져오기      | ODE 모드에서만 명시적 보조식, 상태·파라미터 이름과 중복 금지                |

`A(0)`을 일반 함수 호출로 처리하기 전에 상태 초기조건으로 분류합니다. 번호 있는 함수는 기존 함수·표현식 전처리기를 사용하되 미분 행의 좌변과 초기조건·범위는 별도 구조로 보존합니다. 모든 숫자·연산·내장 함수는 현재 실수 평가기와 같은 정의역 검사를 적용합니다. 분기 조건식을 추가하려면 별도의 이벤트/불연속 처리 계약을 먼저 마련합니다.

## 3. 실행 구조

```mermaid
flowchart LR
  A[수식·초기조건·범위] --> B[ODE 파서 / 의존 DAG]
  B --> C[컴파일한 RHS와 보조식]
  C --> D[Worker의 적응형 RK45]
  D --> E[해 궤적 / 오차 / 종료 상태]
  E --> F[시간 그래프 / 위상도 / 데이터 / 리포트]
```

현재 식 평가 AST, 실수 함수, 프로젝트 저장, 요청 번호·오래된 응답 폐기, 그래프 축·포인터 도구와 CSV 코드는 재사용합니다. `solveNear`·접점 탐색을 시간 적분기로 사용하지 않습니다. 처음에는 검증하기 쉬운 TypeScript 수치 코어를 Worker에서 실행하고 동일 계약의 WASM 모듈을 이후 추가합니다. 엔진 표시와 fallback 이유를 실제 실행 상태에 맞게 표시합니다.

보조식 DAG는 한 번 정렬합니다. RHS 평가 때 t·상태 벡터·파라미터를 주입하며, 보조식을 의존 순서로 계산합니다. 평가 중 식 문자열을 다시 파싱하지 않습니다. 일반 이름의 식을 JavaScript 코드로 실행하지 않습니다.

제안하는 출력 계약은 다음과 같습니다.

```typescript
type OdeStatus =
  | 'completed'
  | 'domain-boundary'
  | 'step-underflow'
  | 'iteration-limit'
  | 'nonfinite'
  | 'cancelled'

type OdeTrajectory = {
  status: OdeStatus
  independentVariable: string
  stateNames: string[]
  sampleTimes: Float64Array
  // 행 우선: values[row * stateNames.length + state]
  values: Float64Array
  lastAcceptedTime: number
  acceptedSteps: number
  rejectedSteps: number
  tolerances: { rtol: number; atol: number[] }
  engine: 'javascript' | 'wasm'
  message?: string
}
```

프로젝트는 `kind:'ode'`와 버전을 가진 별도 저장 구조를 사용합니다. 현재 LEQ/NLE 파일을 추측으로 ODE로 바꾸지 않습니다. 사용자 조작에 따른 재적분은 최신 요청만 채택하고, 큰 배열은 Worker transfer로 전달합니다. 작업 중단을 받으려면 한 거대 동기 루프 대신 시간/스텝 예산별로 제어권을 반환합니다.

## 4. 수치 코어

첫 솔버는 Dormand–Prince RK45입니다. 상태별 오차 척도는 `atol[i] + rtol * max(abs(yOld[i]), abs(yNew[i]))`로 계산하고 정규화한 오차가 기준을 넘는 스텝은 거부합니다. 최소 스텝에서도 허용 오차를 만족하지 못하면 `step-underflow`로 종료합니다. 최소 스텝 도달을 성공 승인 조건으로 사용하지 않습니다.

상태별 절대 오차, 상대 오차, 최대 스텝·최대 반복·최대 출력 행을 검증합니다. 기본값은 사용자에게 설정으로 표시하며 물리적 정확도 보장으로 설명하지 않습니다. 마지막 스텝을 종료 시점으로 제한하고 역방향 적분도 같은 부호 규칙으로 처리합니다.

적분기의 내부 스텝과 **출력 샘플 간격**은 분리합니다. 표·CSV의 시간 격자는 정확한 소수 격자로 만들고 검증한 RK dense output으로 샘플합니다. 정의역 실패·미승인 스텝을 보간으로 연결하지 않습니다. 로그·제곱근·분모의 RHS 정의역 이탈은 스텝을 줄여 다시 평가하고, 안전한 마지막 지점과 종료 이유를 남깁니다. 이벤트 근을 브래킷할 수 있을 때만 경계 위치를 재검증합니다.

강성 감지는 잦은 스텝 거부 등 **진단 안내**로 시작합니다. BDF/Radau가 실제로 구현·검증되기 전에는 자동 전환했다고 표시하지 않습니다. 향후 암시적 솔버는 야코비안·선형계·수렴 실패 계약을 따로 검증합니다.

## 5. 화면과 시뮬레이션

기존처럼 한 화면에서 한 작업을 하도록 세 화면을 분리합니다.

1. **수식·초기조건:** 미분식, 상태 초기값 목록, 독립변수 범위, 파라미터, 고급 오차 설정. 조건이 빠지면 해당 상태를 지목합니다. 수식의 초기조건과 카드의 초기조건은 단일 모델 상태를 편집하며 이중 저장하지 않습니다.
2. **시뮬레이션:** 독립변수를 X축으로 하는 다중 상태 그래프와 표. 두 상태를 고르는 2D 위상도를 추가합니다. 그래프 클릭·시간 재생은 이미 계산된 궤적 위의 시점만 바꾸므로 재적분하지 않습니다. 파라미터·초기값 변경은 새로운 궤적을 계산합니다.
3. **리포트:** 완료/중단 상태, 마지막 승인 시각, 사용한 초기조건·파라미터, 상태별 최소·최대와 시각, 허용 오차, 승인/거부 스텝 수, 표·CSV. 단순 스텝 오차 추정치를 전체 해 오차의 보증으로 표시하지 않습니다.

여러 초기값 또는 파라미터 조건을 **비교 실행**으로 고정하고 한 그래프에 색상별로 겹칠 수 있습니다. 같은 초기값 ODE의 유일 궤적과 NLE의 다중 실근을 혼동하지 않도록 ‘해 1/2’ 대신 ‘실행 1/2’로 표시합니다. 각 비교 실행의 파라미터 스냅샷을 보존하고, 현재 슬라이더를 움직여도 고정 실행을 덮어쓰지 않습니다.

재생 커서·호버 때문에 기준 궤적·기본 축을 다시 계산하지 않습니다. 기존 클릭 적용·축 확대/초기화와 전체화면을 재사용합니다. 실패 뒤에는 그래프를 끊고 중단 시각과 이유를 표시합니다. 3D 벡터장이나 입자 애니메이션은 후속 범위로 둡니다.

## 6. 구현 전 검증 목록

- 일차 반응 `A'=-k*A`: 해석해 `A(t)=A0*exp(-k*(t-t0))`와 절대/상대 오차 비교.
- 연속 반응 A→B: `A+B` 보존량, 보조식 순서 독립성.
- 조화진동자: 위상도, 주기, 장시간 에너지 드리프트 및 오차 설정에 따른 수렴 경향.
- 시작 t≠0, 역방향 적분, 끝점 중복 방지, 나누어떨어지지 않는 샘플 격자.
- 로그·제곱근 RHS의 정의역 경계, 분모 0, 발산·underflow, 허용 오차 미달의 실패 상태.
- 강성 문제: RK45가 제한에 도달하면 솔버 한계를 정확히 보고하는지 검사.
- Worker 취소·응답 역전·저장 복원·비교 스냅샷·클릭/재생 중 곡선 불변성·모바일.
- WASM 추가 시 JavaScript와 독립 해석해에 대한 일치 검사. 성능은 동일 모델·기기·허용 오차로 측정한 뒤 보고.

이 설계를 먼저 검토 가능한 계약으로 남깁니다. 현재 브랜치에서 실행되는 계산기는 Equation Solver이며, ODE 구현·검증 결과로 오해할 화면이나 완료 배지는 추가하지 않았습니다.
