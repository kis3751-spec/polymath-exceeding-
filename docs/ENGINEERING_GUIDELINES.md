# 개발 시 고려할 기준

현재 목표는 Equation Solver의 정확성·반응성·사용성 개선과 승인된 과학 계산 모듈의 확장입니다. 이 문서는 사용자 의견서를 검토하면서 확인한 사항을 이후 구현에 남깁니다. 의견서의 패치·로드맵·성능 숫자는 검증할 제안이며 사용자 지시를 대신하지 않습니다. 2026-11-09 사용자가 미분방정식, 회귀, 최적화, 적분 구현을 명시적으로 승인했습니다. 기존 Equation Solver 문법·프로젝트·결과 검증을 보존하면서 각 계산 모듈을 독립 Worker 경계에 연결합니다.

## 문법과 기존 모델의 의미

- 문자열을 JavaScript로 실행하지 않고 제한된 토큰·구문 트리와 함수 목록으로 평가합니다. 길이·중첩·미지수 개수 제한과 원래 입력 행 정보를 유지합니다.
- `f(min)`, `f(max)`, `f(0)` 같은 조건식과 `f(f)` 같은 근 정의가 충돌하지 않도록 좌변을 분류합니다. `min(x, 1)`처럼 함수 인수가 있는 수식은 조건식과 구분합니다.
- 단항 부호·거듭제곱·곱셈의 우선순위를 두 파서에서 검증합니다. `-2^2`, `(-2)^2`, `2^-2`, `2^3^2`를 서로 다른 사례로 취급합니다. 이미 맞는 동작을 의견서의 설명만 보고 다시 작성하지 않습니다.
- 허용한 암묵적 곱셈을 문서화합니다. `2x`, `2(x+1)`, `(x+1)y`의 지원이 `x(y+1)`을 함수인지 곱셈인지 자동 추측한다는 뜻은 아닙니다.
- 함수 호출의 대소문자 허용과 변수 이름의 대소문자 구분은 별개입니다. `SIN(x)`을 허용해도 `x`와 `X`를 합치지 않습니다.
- 일반 등식 모드의 `x=2`, 두 행으로 적은 `x=y`와 `y=2`, 두 행으로 적은 `k=4`와 `x^2=k`는 미지수에 대한 방정식입니다. 보조식 추론을 추가한다는 이유로 이 의미를 바꾸지 않습니다. 상수는 UI 파라미터로 등록하고, 수식 재사용에는 번호 있는 함수·식 정의를 사용합니다.
- 선형 모델에는 `e`를 미지수로 사용하는 기존 예제가 있습니다. 선형의 `e`, `pi`를 비선형 내장 상수와 같게 바꾸려면 호환성·표현 방법을 먼저 설계합니다. 단순 예약어 추가로 기존 모델을 깨뜨리지 않습니다.

## 수치 계산과 분기 추적

- 유한한 입력·정의역·분모·피벗·반복 종료를 검증하고, 계산 실패와 해 부재의 수학적 증명을 구분합니다. 조건수는 진단이며 작은 잔차만으로 정확도를 보장하지 않습니다.
- 허용치는 상대 오차, ULP와 잔차를 함께 고려합니다. 고정된 `1e-12` 근처를 모두 0으로 만드는 처리는 `1e-15` 크기의 서로 다른 근을 없앨 수 있습니다.
- 0 교차·중근·기울기 0·극점·정의역 경계·매우 작은 근·먼 주기의 근을 함께 검증합니다. 정상 분기를 살리는 변경이 다른 주기로의 점프나 실근 없는 구간의 연결을 허용하지 않아야 합니다.
- 그래프·표 격자가 특이점을 정확히 포함하는 검사와, 현재값 추적이 그 점을 밟지 않고 건너가는 검사를 함께 수행합니다. 한 경로의 성공을 다른 경로의 성공으로 간주하지 않습니다.
- 끝점에 유일한 다항식 실근이 있다는 사실만으로 파라미터 경로 전체의 연속성을 가정하지 않습니다. 계수의 정의역·분모·최고차항 변화와 짝수 차수의 극점도 확인합니다.
- 해석해가 있는 모델은 해 벡터와 대입 잔차를 비교합니다. 보고서의 예상 숫자·측정 시간은 별도 검증 없이 정답으로 복사하지 않습니다.
- 선택한 해의 기준점은 불변으로 둡니다. 탐색 변수의 현재값만 바꾸면 같은 기준 곡선을 사용하고 현재 지점만 다시 구합니다. 다른 고정 파라미터, 기준 해, 범위가 바뀌면 곡선 재계산이 필요할 수 있습니다.
- 추적하지 못한 구간은 빈 값과 이유로 남깁니다. 교차점·분기점에서 수치적 연속성이 가지의 수학적 동일성을 증명한다고 표시하지 않습니다.
- 다항식 차수·시간·표시 근 수·탐색 범위 제한을 결과와 문서에 드러냅니다. 일반 함수 경로로의 전환을 모든 실근 탐색으로 설명하지 않습니다.
- 직접 SVD, 행 정규화, 보상 합산과 정밀한 소수 격자 같은 기존 방어를 보존합니다. 향후 회귀를 구현한다면 정규방정식이 조건수를 악화시키는 점을 검토하고 QR/SVD 등을 비교합니다. 이는 현재 새 모듈을 구현하라는 지시가 아닙니다.

## 상태·워커·저장과 화면 조작

- 파싱, 수치 계산, 작업 요청, 표시 상태를 구분합니다. 요청 번호로 오래된 응답을 버리고, 작업 큐는 최신 입력을 우선합니다.
- 고정 해의 현재값을 먼저 계산하는 경로와 전체 해 목록 탐색을 구분합니다. 뒤로 미룬 전역 탐색이 끝나기 전에는 이전 목록·범위를 현재 파라미터의 결과처럼 표시하지 않습니다.
- 첫 계산에서 얻은 앵커와 곡선을 UI가 채택할 때 동일한 계산을 자동 재요청하지 않도록 요청 입력과 식별자를 일관되게 관리합니다.
- 수식 입력을 잠시 모으는 지연과 슬라이더·해 선택 지연을 구분합니다. 실제 장치·모델에서 응답성을 확인하고, 근거 없이 일정 프레임률이나 개선율을 보장하지 않습니다.
- 자동 저장을 미뤄 메인 스레드의 반복 직렬화를 줄이되 마지막 변경을 잃지 않도록 합니다. 페이지 숨김·종료와 모델 전환 시 남은 변경의 저장·정리 경로를 검토하고, 저장소 접근 실패는 화면에 표시합니다.
- 그래프 호버 보간값과 솔버의 직접 계산값을 구분합니다. 클릭으로 파라미터가 바뀌면 실제 모델을 다시 풀며, 보간값을 계산 결과로 저장하지 않습니다.
- 호버·현재 표시점 때문에 축이나 기준 곡선을 다시 맞추지 않습니다. 화면 좌표 변환, 끊긴 구간, 그래프별 확대 상태, 키보드·모바일 조작을 확인합니다.
- CSV 출력은 공통 셀 이스케이프와 일관된 줄바꿈을 사용합니다. 유효한 식별자에서 현재 문제가 재현되는지와 형식의 잠재적 불일치를 구분합니다.

## 검증과 문서 유지

- 의미 있는 수치 변경에는 원래 실패 사례와 인접한 실패·성공 사례를 추가합니다. 구현을 그대로 따라 쓰는 검사보다 해석해·잔차·요청 순서·사용자 동작을 검증합니다. 단순한 문구·배치 변경만을 위한 과도한 테스트는 피합니다.
- `npm test`와 `npm run build`는 `public/solver.wasm`을 갱신합니다. 이를 끝낸 뒤 소스를 고정하고 브라우저 검증을 실행해 HMR 재로딩이 테스트 실패를 만들지 않게 합니다.
- 파일이 바뀌면 타입·형식·관련 단위 검사를 먼저 실행합니다. 필요한 E2E와 배포 빌드의 실제 동작을 확인하며, 이미 통과한 검사를 이유 없이 반복하지 않습니다.
- 핵심 코드 문서는 원본에서 생성합니다. `npm run docs:core`로 갱신한 뒤 `npm run docs:core -- --check`로 일치를 확인합니다. 검토 결과에는 적용한 개선, 재현되지 않은 주장, 호환성 때문에 채택하지 않은 변경, 남은 한계를 구분합니다.

## 구간 검증

- 검증한 길이 비율은 포획 확률이 아닙니다. 미결정 구간·대기 작업·근 표시 제한을 숨기지 않으며 현재 입력과 실제 검증 범위를 내보냅니다.
- 단조성 판정은 값·도함수의 전체 구간과 끝점의 구간 부호를 사용합니다. 일반 함수값의 곱은 언더플로·반올림 때문에 증명 근거가 될 수 없습니다.
- 초월함수 경계는 해석적 오차 경계가 필요합니다. 임의의 EPS 패딩이나 `Math` 구현에 대한 추정 오차를 인증으로 승격하지 않습니다.
- 구간 분리·수치 보정·결과 목록 대조를 구분하고, 원래 중근 식 대신 단순 인수를 검증했다고 조용히 바꾸지 않습니다. 상세 판단은 `INTERVAL_CERTIFICATION.md`를 확인합니다.

## 일반 등식과 이벤트 안내

- 자동·수동 입력과 안내는 일반 등식으로 통일합니다. 수동 연립식의 변수는 전체 방정식에서 추론하며, 같은 변수가 여러 행의 첫 항이라는 이유로 잘못된 가상 변수를 만들지 않습니다.
- 함수 정의만 적었을 때 임의로 0과 같다고 풀지 않습니다. 명시한 목표 등식과 정의를 구분합니다. 저장 모델 전환은 초기값·파라미터·해 벡터 순서·정의역을 보존합니다.
- 같은 접점의 중복 안내는 거친 추적 중단 위치나 반올림한 표시 문자열 대신 검증한 좌표로 대조합니다. 이벤트 표시 중복 제거와 실제 해의 중복 판정은 분리합니다. 세제곱근 통과를 근 병합으로 안내하지 않습니다.

## 리포트 지표와 스크롤 안정성

- 실제 포함 구간의 오차 상한과 Newton 보정량을 구분합니다. 오차 상한의 화면 숫자는 아래로 반올림하지 않습니다. 현재 소스·파라미터가 다른 인증 자료를 재사용하지 않습니다.
- 단일 변수의 조건수 1을 낮은 절대 민감도의 근거로 쓰지 않습니다. `1/|F′|`와 파라미터 변화율, 중근에서는 첫 비영 도함수의 비선형 반응을 사용하며 가정·단위를 명시합니다.
- 보정이 수렴하지 않은 평탄한 지점을 작은 도함수만으로 낮은 차수 접점으로 승인하지 않습니다. `Fp=0`인 퇴화점과 정칙 fold를 분리합니다.
- 같은 작업 화면 내 추가 동작은 탐색·전체화면 상태를 초기화하지 않습니다. 포인터 포커스에는 `preventScroll`을 사용하며, 갱신 중 목록 비우기로 상단 콘텐츠 높이가 붕괴하지 않도록 합니다.

## 첨부 확률·인증 코드의 통합 기준

- 작은 극값·잔차를 정확한 다항식 중인수로 바꾸지 않습니다. `0∈F(I)`는 존재 증명과 다르며 고차 도함수의 영점 검증만으로 원래 함수의 영점을 확정하지 않습니다.
- 실수 정의역 인증에서는 `nextUp` 사이의 열린 실수 영역도 보존합니다. Float64 격자점의 부재를 실수 근의 부재로 해석하지 않습니다.
- 확률 공간·오차 모델·결합 근거 없이 고정 위험도를 곱해 전체 발견 확률을 만들지 않습니다. Gaussian 안전 반경 사건과 근 개수 유지 사건을 구분하고 탐색 경계 이탈을 포함합니다.
- 2026-11-09 첨부본의 반례와 통합 거부 사유는 [첨부 코드 검토](UPLOADED_PATCH_AUDIT.md)를 참고합니다.

## 2차 검토 이후의 그래프·초기값 기준

- 표·CSV의 샘플 점은 그래프 선을 만드는 실제 계산점에도 포함합니다. 마커를 보간선에 맞춰 이동시키지 않습니다.
- 초기값은 최초 기준 해를 선택합니다. 샘플마다 같은 초기값으로 독립 Newton을 재시작하여 다른 근을 연결하지 않습니다. 명시적인 재계산과 파라미터 이동을 구분합니다.
- Float64의 가장 작은 양수보다 작은 **실수**도 포함해야 합니다. 부호를 보존한다는 이유로 구간 하한을 MIN_VALUE로 올리지 않습니다. 2차 후보의 반례는 [재검토 기록](UPLOADED_PATCH_V2_AUDIT.md)을 참고합니다.

## 3차 확률·인증 검토 이후

- Float64로 반올림한 다항식 계수를 exact arithmetic으로 평가해도 원래 AST의 인증은 아닙니다. 후보 계수 생성과 원본 식의 실수 포함성·영점 동치 증명을 구분합니다.
- Gaussian CDF 상하한에는 함수 근사 오차와 산술 반올림을 모두 포함합니다. 마지막 합의 1 ULP 패딩으로 근사 함수 자체를 인증하지 않습니다.
- 중인수 제거식의 도함수를 원래 함수의 섭동·안전 반경 계산에 사용하지 않습니다. `log`의 밑은 점 평가·기호 미분·구간 AD에서 일치해야 합니다.
- 결과 목록 대조 전의 `allRootsRepresented=undefined`를 전체 발견 완료로 승인하지 않습니다. 상세 반례와 분리 적용 범위는 [3차 검토](UPLOADED_PATCH_V3_AUDIT.md)에 있습니다.

## 과학 계산과 확률 엔진 통합

- ODE의 출력 샘플과 내부 적응 스텝을 구분합니다. 최소 스텝·정의역·예산 초과를 성공으로 표시하지 않고 부분 결과와 중단 사유를 반환합니다.
- 회귀는 정규방정식 대신 정규화 QR/SVD를 사용합니다. 랭크·자유도·경계 활성 상태 없이 표준오차나 R²를 과대 해석하지 않습니다. 관측 종속값을 보조식으로 몰래 모델 입력에 넣지 않습니다.
- 최적화는 국소 정상성·제약 위반과 수렴 상태를 함께 보고하며 전역 최적 보장을 하지 않습니다. 실패·최대 반복을 수렴으로 표시하지 않습니다.
- 이산 적분은 보간 모델을 명시하고 표 범위 밖 외삽을 승인하지 않습니다. 서로 다른 x축/단위의 데이터·누적량·수렴 이력은 별도 그래프 모드로 나눕니다.
- 파라미터·모델이 바뀌면 과거 결과를 현재 수치로 내보내지 않습니다. 새 Worker 요청은 이전 계산을 종료하고 결과 ID를 확인합니다. 표는 페이지로 표시하고 CSV에는 전체 행을 보존합니다.
- 검증된 확률 범위는 원래 함수와 유한 범위의 명시적 단일 Gaussian 오프셋에 한정합니다. 목록 대조 전 100% 승인과 미산정값의 0% 대체를 하지 않습니다. Markdown 내보내기도 화면과 같은 바깥쪽 반올림 원칙을 유지합니다.

## IVC 화면·교재·통계 표기

- 제품 표기는 Interaction Visual Calculator (IVC)로 통일합니다. 기존 브라우저 저장 키·프로젝트 호환성은 이름 변경과 별개로 보존합니다.
- 모든 모듈은 동일한 compact toolbar와 Model & Data / Simulation / Report 흐름을 사용합니다. Technical terms는 English, 사용법과 지표 해석은 한국어로 설명합니다. 핵심 결과·계수·2~3개 지표를 우선 보여주고 고급 진단·가정은 접어 둡니다.
- User Guide는 Linear / Nonlinear / ODE / 각 회귀 / Integration / Optimization / LSQ의 독립 탭입니다. 새 기능은 해당 탭에 입력 예제, 예상 결과, 숫자 해석, 알고리즘의 역할, 지원 범위·오해를 함께 갱신합니다. 초보자가 다른 모듈의 설명을 읽어야만 시작할 수 없게 합니다.
- 회귀 선택 UI는 polyfit 명령 등 실제 Input을 수정합니다. UI와 문법에 서로 다른 숨은 설정을 만들지 않습니다. 기존 입력을 바꾸면 계산 결과와 다운로드는 최신 작업 완료 전까지 stale로 처리합니다.
- 95% CI는 유한 Degrees of Freedom의 Student-t 임계값과 계수 공분산을 사용합니다. RMSE, R², Prediction Interval, 수치 오차 상한, Gaussian root-count 확률과 구분합니다. Origin 고정 계수·자유도 부족·활성 경계·수렴 실패·최종 Jacobian의 미분 불가 차분 대체를 일반 CI로 표시하지 않습니다. 중앙차분의 가짜 full rank를 통계적 식별 근거로 승격하지 않습니다. 비선형 CI는 Local Approximation이라고 명시합니다.
- 적분 음영은 실제 계산 범위를 표시하고 signed integral과 연결합니다. 출력 샘플을 늘리는 행위와 측정 데이터·수치 정확도 증가를 혼동하지 않게 합니다. Phase Plot의 X/Y 축에는 실제 선택한 변수를 표시합니다.

## 서버 인증과 초대 전용 공유

- 공개 소개와 계산기 파일은 서버에서 분리합니다. React 화면 숨김·localStorage 역할·테스트 플래그로 인증을 대신하지 않습니다. dev/preview도 같은 보호 서버를 통과합니다.
- 비밀번호 원문·실제 세션·초대 링크·DB를 커밋하지 않습니다. 초기 관리자 설정은 서버의 숨김 입력/비밀 환경값으로 수행합니다. 최고 관리자 ID는 DB 설정에 고정하고 모든 관리자 요청에서 검증합니다.
- 로그인 쿠키는 운영 HTTPS에서 Secure/HttpOnly/SameSite/Host 경계를 적용합니다. 만료·회수는 서버가 결정하고 POST는 Origin/CSRF를 검사합니다. 관리자 쓰기는 비밀번호 재확인을 요구합니다.
- 초대 수락·권한 회수·비밀번호 변경은 토큰/기존 세션 상태를 다시 확인합니다. 해시 이후 비동기 경쟁에서 회수된 계정을 살리지 않습니다. 비매개변수 SQL, 공개 부트스트랩 API, 프록시 헤더 무조건 신뢰를 허용하지 않습니다.
- 수학 엔진 수정 없이도 로그인·파일 보호·권한·초대·세션에 실제 HTTP/브라우저 검증을 유지합니다. 이미 배달한 클라이언트 계산 코드나 내보낸 모델을 회수할 수 있다고 주장하지 않습니다. 운영 범위는 ACCESS_CONTROL.md에 기록합니다.
