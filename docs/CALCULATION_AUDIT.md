# Equation Solver 계산 안정화 검토

이번 변경은 첨부 코드 묶음 3개와 사용자가 보고한 반데르발스 유리식·다중 등식·붙여넣기 문제를 검토한 결과입니다. 현재 Equation Solver의 실수 계산에 적용하며 새 계산 카테고리는 추가하지 않았습니다. 아래의 수치 검증과 지원 범위를 완료 기준으로 삼습니다. 임의의 방정식을 기호적으로 증명하거나 모든 해를 보증하는 계산기는 아닙니다.

## 재현과 독립 기준값

`a=3.59, b=0.0427, R=0.08314`의 임계온도를 65자리 mpmath 계산으로 확인하면 다음과 같습니다.

```text
Tc = 8*a/(27*R*b)
   = 299.62826273217199839093780579009917632900001174726406115688266672 K
```

첨부 설명의 299.625 K와 작은 차이가 있지만, **300 K는 임계온도를 넘는다**는 결론은 같습니다. 280 K·53 bar에서는 다음 세 몰체적을 독립 고정밀 계산으로 확인했습니다.

| 구분    |                                V (L/mol) |
| ------- | ---------------------------------------: |
| 작은 근 | 0.08535041004713538201387710611023236785 |
| 중간 근 | 0.12459268535944403077328985739129203917 |
| 큰 근   | 0.27198709327266587023170096102677747978 |

이전 엔진에서 원래 유리식 `(P+a/V^2)*(V-b)=R*T`를 계산하면 작은 근을 놓치고 두 개만 찾는 현상을 재현했습니다. 수정 후 세 근을 찾으며 독립식 `P=R*T/(V-b)-a/V²`에도 대입해 압력을 확인합니다. 함께 검증하는 삼차식은 다음과 같습니다.

```text
P*V^3 - (P*b + R*T)*V^2 + a*V - a*b = 0
```

원래 식에서 `V=0`은 제외합니다. 물리적인 기체 모델에는 추가로 `V>b` 조건이 필요하지만, 수학적 실근을 물리 조건으로 조용히 걸러내지는 않습니다. 280 K의 양의 물리적 극값 압력은 약 **47.156319, 58.750163 bar**입니다. 추가한 단위 있는 예제는 기본 P=53 bar에서 시작하고 45~62 bar를 탐색하여 두 분기 끝점을 포함합니다.

## 적용한 계산 변경

### 1. 다항식·유리식 후보 생성과 원래 식 검증

- 제한된 AST의 대수 연산에서 유리식 분자·분모 계수를 구성합니다. 음의 정수 거듭제곱과 `pow`도 처리하며 함수 호출을 JavaScript 소스로 실행하지 않습니다.
- 지원 차수 안에서 분자 다항식의 실근 후보를 기존 미분 임계점 기반 실근 분리기로 찾습니다. 분모가 있는 원래 식에 다시 대입하여 정의되지 않는 후보를 제외합니다. `(x²−1)/(x−1)=0`에는 −1만 남고, `(x−1)²/(x−1)=0`에는 해가 없습니다.
- 곱으로 주어진 식은 인수 자체에서도 후보를 구합니다. 전개 중 유효숫자를 잃어 `(x−1)*(x−1.00000001)`의 두 근을 합쳐 버리는 것을 방지합니다. 후보는 원래 전체 식으로 재검증합니다.
- 잔차가 정확히 0이 아닌 대수 후보에는 국소 잔차와 Newton 보정량의 반올림 크기를 함께 확인합니다. `(x−1)²+1e−20=0`의 양의 최솟값을 실근으로 오인하던 사례를 차단했습니다.
- 분자 다항식의 근이라는 이유만으로 유리식 분기를 ‘극점 없는 유일 다항식 근’으로 인증하지 않습니다. 기존 파라미터 경로 가드를 유지합니다.

### 2. AST 자동미분

`expression-derivative.ts`에서 기존 AST를 전진 모드로 미분합니다. 다항식·유리식, 지수·로그·삼각·쌍곡·역삼각 함수와 보조식 의존 관계를 같은 변수 순서로 처리합니다. 매끄러운 식의 스칼라 보정과 연립 Newton의 Jacobian에 사용합니다.

`abs(0)`, `sqrt(0)`, 기울기가 다른 `min/max`의 교차 등에는 없는 도함수를 만들지 않습니다. 이 경우 기존 정의역 보호 수치 차분으로 보완하며, 특이성·수렴 실패 상태를 유지합니다. 자동미분도 Float64 연산이며 임의 정밀도 연산이나 미분의 기호 증명은 아닙니다.

### 3. 가까운 해의 중복 판정

엔진·Worker·화면의 고정된 `2e−7` 상대 판정을 공통 `sameComputedRoot`로 바꿨습니다. 잔차에 대한 국소 보정 `J*dx=-F`와 반올림 크기를 이용한 **중복 판정용 오차 추정**입니다. 엄밀한 해 오차 상계가 아닙니다. 같은 근 후보를 합칠 때는 더 작은 잔차의 결과를 보존합니다. 1과 1.00000001을 별개로 탐색하고 각각 시뮬레이션에 추가하는 경로를 검증합니다.

### 4. 고정 조건 소거

`a=3.59, b=0.0427, ...`는 일반 등식의 의미를 유지합니다. 숫자나 이미 고정된 값으로 확정되는 등식은 내부적으로 소거하여 남은 미지수 문제를 풉니다. 결과에는 **원래 변수와 고정된 값 모두**를 복원하고, 원래 전체 잔차와 Jacobian을 계산합니다.

따라서 `k=4; x²=k`는 k를 몰래 보조식으로 바꾸지 않고 `(k,x)=(4,2),(4,−2)`를 반환합니다. `x=y+1; y=2`도 x와 y 모두 결과에 남습니다. 외부 파라미터나 보조식·미지수의 기존 구분은 유지합니다.

### 5. 일반 함수의 탐색 격자

기존 전역 격자에 원점 주변 조밀 격자와 로그 크기별 격자를 더했습니다. `ln(x)=-230.25850929940458`처럼 작은 양수 영역에 있는 근도 검사합니다. 사용자가 지정한 범위 밖으로 확장하지 않으며, 여전히 유한한 탐색입니다. 조밀 격자만으로 모든 초월함수 근을 보장하지 않습니다.

## 입력·편집기 변경

- 괄호 깊이를 확인하고 최상위 쉼표·세미콜론에서만 등식을 나눕니다. `max(x,2)`의 인수 쉼표는 유지합니다. 숫자 대입이 명확한 `a=2 b=4`도 지원합니다. 복잡한 식은 쉼표나 세미콜론으로 구분합니다.
- `2x+y=x-y+8=10`은 두 등식으로 풀며 결과는 x=4, y=2입니다. `f1(x)=2x+4=0`은 함수 정의와 영점 조건으로 나눕니다. 이미 정의한 `f1=f2=0`도 두 영점 조건이 됩니다.
- 숫자 뒤 공백과 괄호의 알려진 단위 표기는 주석으로 읽습니다. `280 (K)`, `3.59 (L^2·bar/mol^2)`가 해당합니다. 해당 기호가 다른 식의 변수나 외부 파라미터라면 곱셈으로 유지합니다. **환산·차원 검사는 하지 않으므로 일관된 단위 체계가 필요합니다.** 곱셈에는 `2*K`를 권장합니다. 단위 주석을 일반 수식의 임의 괄호 삭제로 구현하지 않았습니다.
- 입력 정규화로 늘어난 논리적 행의 진단은 원래 물리적 행으로 매핑합니다. 함수 전개 등 복잡한 내부 변환의 진단은 해당 변환의 범위에도 영향을 받을 수 있습니다.
- 붙여넣기는 일반 텍스트를 사용하고 코드 펜스·CRLF·특수 마이너스를 정리합니다. 세 행 이상에서 매 행 사이 빈 행이 반복되는 패턴은 복사 과정의 중복 행으로 정리하고, 일반적인 빈 단락은 유지합니다.
- 에디터는 행 수에 따라 높이가 늘고 긴 입력은 최대 높이에서 스크롤합니다. 줄바꿈을 자동 접지 않으며 28px 행 높이와 줄 번호 스크롤을 동기화합니다. 줄 번호는 실제 텍스트 행, 방정식 개수는 나눈 논리적 등식 수입니다.

## 첨부 코드에서 그대로 가져오지 않은 부분

유리식 후보 추출과 입력 확장의 방향을 채택하되 현재 엔진에 맞춰 다시 검증했습니다. 첨부 묶음에는 기존 워커 요청 순서·저장 검증·해 정렬·공식집 레이아웃을 이전 상태로 되돌리는 차이가 있어 전체 파일 교체는 하지 않았습니다. 단위처럼 보이는 토큰이 일부 들어간 모든 괄호를 삭제하는 정규식도 채택하지 않았습니다. 제시된 0.02ms 성능 수치는 재현한 벤치마크가 아니므로 이번 결과로 인용하지 않습니다.

## 지원 범위와 완료 기준

현재 계산은 Float64 기반입니다. Linear는 최대 64개, 자동 Nonlinear는 최대 16개 미지수를 지원합니다. 다항식·유리식 분리의 지원 차수는 12이고, 그 범위를 벗어나면 일반 수치 탐색으로 전환될 수 있습니다. 일반 탐색의 기본 범위는 −100~100, 표시 근 수는 최대 32개, 탐색 시간 예산은 1.8초입니다. 실제 범위·방법·제한 도달 여부를 결과에 표시합니다.

유한한 초월함수 탐색의 완전성, 강한 상쇄·언더플로·오버플로가 있는 식, 극도로 가까운 ill-conditioned 근의 엄밀 분리, 다변수의 모든 해 발견은 보장하지 않습니다. 조건수·작은 잔차만으로 실제 해의 오차 상계를 보증하지 않습니다. 실패를 성공으로 바꾸거나 근 부재를 증명했다고 표시하지 않는 것이 기본 원칙입니다. 남은 접점·분기 범위는 [현재 제한 목록](KNOWN_ISSUES.md)에 유지합니다.

## 검증 결과

- 전체 단위 검사 **392개 통과**. 기존 및 신규 선형·비선형·워커·파서·시뮬레이션·시각화 검사를 포함합니다.
- 반데르발스 유리식/삼차식은 T=270·280·300 K와 P=48·53·58 bar 조합에서 비교했습니다. 300 K의 단일근과 280 K·53 bar의 세 근을 확인했습니다.
- 잔차 스케일 1e−18~1e18, 변수 스케일 1e−9~1e9, 인수형의 가까운 근, 극점·중근·작은 양의 최솟값·점근선·고정 조건을 검사했습니다.
- 자동미분 24개 검사로 독립 해석 도함수·보조식 전파·비매끄러운 점의 보류를 확인했습니다. 행 스케일이 1e−12와 1e12로 다른 연립식의 네 해도 원래 무스케일 식에 대입해 확인했습니다.
- TypeScript 및 프로덕션 빌드, 핵심 코드 문서 3개의 원본 일치 검사를 통과했습니다.
- 최종 프로덕션 빌드의 브라우저 검사 **59/59 통과**. 유리식 세 근·연쇄 등식·가까운 해의 개별 선택·수동 NLE0와 데스크톱/모바일의 붙여넣기·줄 번호 동기화를 포함합니다.
- 근 목록의 표시가 소수 8자리에서 잘리던 부분도 수정해 지정한 유효숫자 설정을 반영했습니다. 표시 자릿수가 해 오차 보증을 뜻하지는 않습니다.
