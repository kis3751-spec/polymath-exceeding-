# 4차 구간 검증·확률 모형 통합

기준: 2026-11-09, `확률검증4차.md`를 현재 Equation Solver에 선별 통합하고 남은 결함을 보완했습니다. 후보의 parser·Newton·분기·접점 파일을 덮어쓰지 않았으므로 기존 입력과 2~8차 근 분류, 수동 초기값 시뮬레이션을 유지합니다.

## 통합한 계산

- Float64 계수로 전개한 뒤 exact 계산하는 대신, **원래 AST에서 dyadic BigInt 계수**를 추출합니다. `(x-1)^4+1e-20`과 `(x-1)^6+1e-20`의 작은 양의 항이 보존되어 실근 없음으로 검증됩니다. 음의 섭동에서는 두 근을 각각 분리합니다.
- 원래 AST 구간과 exact centered Taylor 구간을 교차시켜 포함성을 줄입니다. exact 연산의 비트·정렬 예산을 넘거나 교차 구간이 모순되면 AST 구간 경로로 돌아갑니다. 원본을 반올림한 다항식으로 대신하지 않습니다.
- Gaussian CDF는 interval `erf`를 사용해 함수 근사 오차와 산술 바깥 반올림을 함께 포함합니다. `log` 기호 도함수도 상용로그 밑과 일치시켰습니다.
- 확률은 **현재의 유한 검증 범위**에서 `F(x)+ε=0`, `ε~N(0,σ²)`라는 하나의 상수 오프셋 가정에만 적용합니다. 원래 F와 F′의 모든 임계점이 분리되었을 때만 근 개수 유지 확률 상하한을 제공합니다.
- 구간 검증 완료와 솔버 목록 대조는 별개입니다. `allRootsRepresented===true`인 경우에만 `finalizeCertificateMetrics`가 `grade='certified'`, `allRootsFoundProbability=1`을 설정합니다. 나머지는 추정 포획 확률을 만들지 않습니다.

## 후보에 추가로 적용한 수정

1. 닿는 넓은 근 포함 구간 두 개를 같은 근으로 합치지 않습니다. `x²-1`의 두 근은 서로 다른 것으로 유지합니다.
2. ‘접점이 하나라도 있으면 모든 오프셋에서 근 개수 유지 확률 0’이라는 shortcut을 제거했습니다. `(x²-1)²=0`은 큰 음의 오프셋에서 다시 근이 2개가 되므로 유지 확률이 0이 아닙니다.
3. 단순히 도함수 구간이 0을 포함한다는 이유로 임계점의 존재를 승인하지 않습니다. 미분 AST가 없거나 임계점 분리가 끝나지 않으면 확률을 내지 않습니다. 구간 AD만으로 도함수 부재를 증명할 수 있는 경우는 예외적으로 처리합니다.
4. 근이 있는 끝점을 포함한 닫힌 구간을 `rootFreeIntervals`에 넣지 않습니다. 끝점 근 옆의 나머지 영역은 `openLo`/`openHi`로 열린 끝점을 명시하여 기록합니다.
5. 근사 임계점 표본으로 얻는 실수 전체 ℝ 확률은 제공하지 않습니다. 표시된 유한 범위의 검증 결과만 사용합니다.
6. 예전 자동 솔버가 바깥 거듭제곱을 미리 제거해 certifier에 넘기던 경로를 수정했습니다. 이제 원래 AST에서 확률·민감도를 계산하고 영점 동치식은 근 분리에만 씁니다.
7. 파라미터 경로 검사에 필요한 `Record<string, number | Interval>` 상수 API를 복원했습니다. 숨은 극점 차단과 안전한 같은 부호 경로의 정상 추적을 유지합니다.
8. 오차 반경은 마지막 뺄셈도 바깥 반올림하여 실제 실수 거리보다 작아지지 않습니다.
9. 확률 적분의 offset 슬랩 판정은 점 중간값 대신 구간 전체의 순서 관계를 사용합니다. 큰 같은 부호의 끝점을 더해 오버플로하거나, 1 ULP 사이 열린 실수 구간에 Float64 중간값이 없는 경우에도 잘못 분류하지 않습니다.

## 리포트 API

`RootCertificate.completeness`에 다음 정보가 있습니다.

- `grade`, `domainCoverage`, `rootSensitivities`
- `allRootsFoundProbability`: 전체 결과 목록과 대조까지 완료했을 때만 1. 임의 모델의 확률 추정치가 아닙니다.
- `gaussianPerturbation.sigma`
- `gaussianPerturbation.domainRootCountInvarianceBounds`: 가정한 오프셋에서 구간 안 근 개수 유지 확률의 포함 구간
- `gaussianPerturbation.twoSidedSafetyMarginBounds`: 작은 오프셋에서 근 개수 변화가 일어나기 전의 양방향 안전 반경
- `gaussianPerturbation.twoSidedSafetyProbabilityBounds`: 그 안전 반경 안에 오프셋이 있을 확률
- `perturbationUnavailableReason`: 값이 없는 이유. 미결정 길이나 고정 위험도로 대체하지 않습니다.

안전 반경 사건과 근 개수 유지 사건은 다릅니다. 멀리 떨어진 오프셋에서 근 개수가 다시 같아질 수 있기 때문에 두 확률을 합치거나 같은 제목으로 표시하지 않습니다. 입력의 실제 측정 오차 모델이 상수 오프셋 Gaussian과 다르면 이 값으로 실제 신뢰도를 단정할 수 없습니다.

## 검증

기존 3차 확장 반례 127개와 추가 검사 6개가 통과했습니다. 추가 검사는 오프셋 증가 후 근 개수 회복, 접하는 넓은 proof box의 독립성, 홀수 평탄 통과, 식과 σ의 공동 스케일 변경, 끝점 근 옆의 열린 무근 영역, Float64 중간값이 오버플로하는 큰 오프셋 구간을 다룹니다. 100자리 기준의 99개 함수값·도함수 지점, 1,500개 exact fraction 산술 및 300개 dyadic 변환도 포함합니다. 원문은 `tests/v4-probability.test.ts`, 고정밀 기준은 `tests/fixtures/validated-reference.json`입니다.

전체 앱 검사·배포 빌드·브라우저 결과는 통합 작업의 최종 기록을 따릅니다. 남은 한계는 미지원 AST 연산·열린 정의역 경계·일반 다변수 인증·시간/분할 예산이며, 해당 경우 계산 결과와 검증 미완료를 구분합니다.
