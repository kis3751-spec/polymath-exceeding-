# V3 통합·접점 진단 검토

## 반영 범위

첨부 6개 TypeScript 파일과 코드 묶음 3개, 통합 보고서를 현재 원본과 비교했습니다. 보고서의 완료 주장과 숫자는 검증 자료로만 취급했습니다. 실행 경로의 API·저장 형식·해 정렬·작은 근 보존을 유지하며 다음을 반영했습니다.

- `parameter-path.ts`: 파라미터 분모와 퇴화 다항식 경로 검사. `automatic-polynomial.ts`, `root-isolation.ts`, `automatic.ts`, `branches.ts`에서 검증된 정규 다항식 가족에 한해 홀수차 특이점 통과를 허용합니다.
- 첨부 automatic 전체 교체는 기존 해 정렬·빈 해 목록·작은 근 검사에 회귀를 일으켜 채택하지 않았습니다. 기존 전처리·탐색 API와 출력 순서는 보존하고 국소 보정·경로 검사를 이식했습니다.
- 첨부 전처리기의 일반 등식 보조식 추론·추가 이름 규칙은 의미 변경 때문에 채택하지 않았습니다. 번호 있는 함수의 다른 변수 호출·중복 변수 정의 검사를 기존 전처리기에 추가했습니다. 레거시 다변수 잔차 모델은 유지합니다.
- 첨부 패널의 절대 곡률 기준과 분기 기울기만으로 `verified=true`를 반환하는 경로는 채택하지 않았습니다. 첨부 차트의 정점 연결도 직접 대입 검증 없이 곡선을 늘릴 수 있어 채택하지 않았습니다.

## 접점 분류 구현

`src/engine/tangency.ts`는 7점 차분으로 1~4차 도함수를 계산하고, 두 스텝 크기의 차이와 누적 반올림 크기를 오차 추정치로 사용합니다. 중앙 스텐실의 정의역 평가가 실패하면 전진·후진 스텐실로 바꿉니다. Newton 탐색은 4차, 3차, 2차 정상형 순으로 고차 도함수의 영점을 찾고 파라미터를 잔차로 보정합니다. 원래 식의 잔차, 낮은 차수 도함수의 영점, 해당 차수 도함수와 파라미터 도함수의 비영 조건을 모두 확인합니다.

이는 **국소 수치 검증**입니다. `verified`는 기호 증명이나 전역 분기 완전성을 뜻하지 않습니다. 결과의 `bifurcationOrder`, `curvatureFxxx`, `curvatureFxxxx`, `isCusp`와 잔차·기울기를 확인할 수 있습니다. 함수값을 무조건 성공으로 만드는 전역 잔차 허용치 완화는 추가하지 않았습니다. 분류기의 오차 기준은 국소 평가 크기와 도함수 오차에 따라 달라집니다.

- `x^3-p=0`: 3차 변곡 접점. 일반 Cusp catastrophe를 증명하려면 독립적인 두 번째 파라미터와 횡단성 조건이 필요합니다.
- `(x-1)^4-p=0`: 4차 평탄 접점.
- `x*ln(x)+p=0`: `x=1/e, p=1/e`의 2차 접점. `x=0`은 함수가 정의되지 않으므로 접점으로 승인하지 않습니다.
- `sqrt(x)^4-p=0`: 경계에서 유한하고 접선이 0인 단방향 접점의 검사 모델입니다. `sqrt(x)=0` 자체의 무한 기울기를 영기울기 접점으로 잘못 분류하지 않습니다.
- 삼각·쌍곡 모델 `cos((3/pi)*x)-sinh(x)/3-tr=0`: 두 접점에서 원래 식의 잔차와 독립 해석 미분을 검사합니다.

진단은 스칼라 Nonlinear 모델에만 실행합니다. Linear 및 다변수 계산은 기존 행렬 진단을 유지합니다. `MultivariableTangencyProbe`는 SVD 기반 랭크 N−1, 좌·우 영벡터, 방향 2차 도함수와 파라미터 미분을 받는 인터페이스이며 다변수 접점 분류 실행기는 아직 없습니다.

## 기준 곡선과 UI

진단은 기준 곡선을 새로 만들 때 한 번 수행하고 해당 곡선 캐시에 보존합니다. 현재 파라미터 이동으로 `panel.sweep` 배열을 교체하지 않습니다. 검증한 접점 좌표는 별도의 차트 마커와 배너·툴팁으로 표시합니다. 추정 정점을 곡선에 임의 연결하지 않습니다. 기존 추적 경계는 보수적인 현재값 경로 차단에 유지하고, 내부의 3차 변곡 접점은 `contact` 이벤트로 구분해 경로를 차단하지 않습니다.

개별·병합 차트가 동일한 차수별 배너를 사용합니다. 사이트 상단 **사용 가이드 · 공식집**에서 실제 지원 함수와 문법을 확인할 수 있습니다.
