# 함수 문법·연속 파라미터·병합 세트 통합 기록

사용자가 제공한 7개 파일을 현재 프로젝트의 파서, Worker, 저장 형식, UI에 맞춰 통합했습니다. 첨부 가이드의 검증 완료 주장은 그대로 채택하지 않고 저장소에서 재검증했습니다. 새 계산 카테고리는 추가하지 않았습니다.

## 사용 방법

### 함수 정의와 방정식

Linear 및 Nonlinear의 기본 자동 모드에서 다음과 같이 입력합니다.

```text
f1(x) = 2x + 4
f2(x) = -3x + 7
f1(x) - f2(x) = 0
```

해는 `x=0.6`입니다. 정의 이후 같은 함수 좌변이 다시 나오면 `f1(x)=0`처럼 방정식으로 사용할 수 있습니다. 정의를 바꾸려면 처음 정의한 행을 수정합니다. 권장 표기는 번호가 다른 함수 이름입니다.

다른 미지수를 혼합하는 식에는 괄호를 붙이지 않습니다.

```text
f1 = 2x + y - 10
f2 = x - y - 2
f1 + f2 = 0
f1 - f2 = 0
```

해는 `x=4, y=2`입니다. `f1(y)=-3x+7`은 변수 불일치로 안내합니다. 조절할 상수는 파라미터로 등록합니다. 서로 참조하는 함수 정의와 지나치게 큰 전개는 거부합니다. `f1(f2(x))` 같은 합성도 지원합니다.

기존의 단독 `f(x)=잔차식` 모델과 일반 등식의 의미는 유지합니다. 번호 있는 정의 또는 함수 간 연산이 있는 모델에서 새 전처리기를 사용합니다. 수동 고급 모드의 새 문법은 Worker에서 기존 잔차 형식으로 변환하며 초기값·구간 조건도 유지합니다. 이 경로는 기본 자동 모드보다 추가적인 모델별 검증이 필요합니다.

### 연속 값과 샘플 간격

슬라이더의 `step`은 `any`이며 숫자 입력·그래프 클릭도 연속 값을 적용합니다. 저장 형식의 기존 `Parameter.step`은 호환성을 위해 이름을 유지하되 UI에서는 **샘플 포인트 간격**으로 부릅니다. 이 값은 표·CSV·그래프 샘플 마커에 적용하며 이동 폭을 제한하지 않습니다. 그래프의 샘플 마커는 체크박스로 표시 여부를 바꿀 수 있습니다.

Linear의 표는 최대 2,000행, Nonlinear는 최대 500행입니다. 한도를 넘으면 샘플 간격을 임의 변경하지 않고 안내합니다.

### 병합 세트

시뮬레이션 화면의 **시뮬레이션 병합 세트 추가**로 `병합 세트 1`, `병합 세트 2` 등을 만듭니다. 최대 6개의 기준 해를 공유하며 병합 세트도 최대 6개입니다. 세트별 해 선택 칩, 표시할 미지수, 그래프 탐색·축 확대 상태와 CSV가 분리됩니다. 개별 해 시뮬레이션도 유지합니다. 세트·포함된 해는 프로젝트 JSON과 자동 저장에 보존됩니다.

서로 다른 해는 색으로 구분합니다. 원래 선택하지 않은 새 해는 현재 해 목록에서 선택해 기준 해를 추가해야 하며, 이미 있는 세트에 자동으로 넣지 않습니다.

## 수치 처리에서 조정한 부분

- 거친 격자 사이에서 추적이 실패하면 성공·실패 구간을 추가로 나누어 **검증된 끝점들**을 그래프에 넣습니다. `(x-1)*(x-2)*(x-3)=tr`의 `tr=0.38` 부근에 실제 해가 있는데 곡선이 0.35에서 끊기는 사례를 검증했습니다.
- 현재값 계산은 가까운 검증 곡선 지점에서 이어서 풉니다. `x^3=2-a`, 표 간격 0.1의 기준 `a=0`에서 현재 `a=3`이 -1로 표시되는 검사를 추가했습니다.
- 현재 점을 매번 곡선에 끼워 넣는 첨부 방식은 사용하지 않았습니다. 같은 기준점·범위에서 현재 파라미터만 바꾸면 곡선 배열과 기본 축을 유지합니다.
- 첨부의 고정 절대 오차 완화, 큰 부호 변경을 곧바로 극점으로 판단하는 검사는 가져오지 않았습니다. 기존 작은 근·먼 주기·역방향 복귀 방어를 유지합니다.
- 추적 실패를 곧바로 해 소멸의 증명으로 표시하지 않습니다. 기본 표시는 **추적 경계**입니다. 서로 다른 해의 경계 파라미터·값이 가깝고 이전 공통 샘플보다 거리가 줄어든 경우 **병합·소멸 후보(수치 추정)**로 표시합니다. 수학적으로 분기점을 증명하는 기능이 아닙니다.
- CSV는 메인·개별·병합 화면 모두 공통 셀 이스케이프와 CRLF를 사용합니다.

## 남은 한계와 인계 사항

1. 분기 끝점은 추적기의 수치적 경계입니다. 실제 극값에 극도로 가까운 값, 특이점을 밟지 않는 격자, 복잡한 연립식에서는 여전히 수렴 실패가 가능합니다. ‘현재 분기 추적 불가’는 실근 부재의 증명이 아닙니다.
2. 독립 함수 `continueRoot`의 일반 특이점·파라미터 극점 문제 전체를 해결한 것은 아닙니다. 기존 [인계 문서](KNOWN_ISSUES.md)의 직접 API 경로와 짝수 극점·최고차항 소실 사례는 계속 검토 대상입니다. 이번 변경은 검증된 곡선 지점을 현재값 계산에 활용하고, 이미 실패한 경계 너머를 임의 재연결하지 않습니다.
3. 병합 후보 검출은 근접성과 수렴 추세를 이용한 표시입니다. 교차·접촉·소멸을 모든 식에 대해 엄밀히 분류하거나 새 분기를 자동 생성하지 않습니다. 이미 선택한 기준 해의 추적을 비교합니다.
4. 새 문법에서는 `f1`, `f2` 등 번호 있는 이름을 정의에 사용합니다. 기존 파일에서 같은 이름을 일반 미지수로 사용한 경우 이름 변경이 필요할 수 있습니다. 단독 레거시 `f(x)` 표기는 기존 잔차 모드로 남아 있으므로 새 함수 모델에는 번호 있는 이름을 권장합니다.
5. 첨부 전처리기의 모든 문법 조합을 보장하지 않습니다. 함수명·파라미터명 충돌, 같은 이름의 여러 인자 오버로드, 조건식과 사용자 함수의 복잡한 혼합은 추가 검증 대상입니다. 미정의 호출·순환 참조는 실행하지 않고 오류로 처리합니다.

범위를 넘어서는 검사는 이번 작업을 붙잡지 않고 이 기록에 남깁니다. 실행 경로에 들어간 원본은 기존 세 개의 핵심 코드 Markdown에도 다시 생성합니다.

## 검증 결과

- 단위 검사 315개 통과, TypeScript 및 프로덕션 빌드 통과.
- 브라우저 시나리오 45개 확인. 전체 실행에서 실패한 3개는 연속 슬라이더 사양 반영과 키보드·표 툴팁 수정 후 선별 재실행으로 통과했습니다.
- 최종 프로덕션 빌드에서 새 함수 문법, 연속 값·샘플 마커·병합 세트 저장 복원, 분기 끝점 부근 해 표시의 3개 브라우저 검사를 추가로 통과했습니다.
- 핵심 코드 Markdown 3개를 재생성하고 원본과의 일치를 확인했습니다.
