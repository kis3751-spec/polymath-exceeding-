# 스칼라 구간 검증 통합·첨부 코드 검토

## 적용한 기능

**Nonlinear → 수식·파라미터 → 고급 탐색 설정 → 구간 검증 사용**을 켭니다. 추가 계산이 필요하므로 기본값은 꺼짐입니다. 프로젝트 JSON·자동 저장·Worker 요청과 탐색 캐시 키에 설정을 포함합니다.

결과 탐색과 해석 리포트의 탐색 설명에서 **구간 검증 완료 / 보류**, 검증한 정확한 범위, 단순근의 유일성 구간, 미결정 구간과 사유를 확인할 수 있습니다. **구간 검증 저장**은 근을 찾지 못한 화면에서도 입력 모델·파라미터·모든 유일근 구간·모든 미결정 구간을 Markdown으로 내보냅니다. 화면의 구간 목록은 길어질 경우 24개까지만 표시합니다.

구간 검증으로 찾은 유일근 구간에 기존 결과가 없으면 수치 보정을 시도합니다. 기존의 원래 식 대입 검사를 통과한 결과만 목록에 추가합니다. 예를 들어 `cosh(1000000*(x-0.1234567))=2`를 `[-1,1]`에서 계산하면 기존 점 탐색에서는 놓쳤던 두 근 `0.1234567 ± acosh(2)/1000000`을 구간 분리·보정으로 복원합니다. 구간 분리와 소수 근의 보정은 별개입니다. 구간은 분리했지만 보정이 실패하거나 표시 한도 32개에 걸리면 **계산 결과 목록과 대조 필요**를 표시합니다.

현재 파라미터에서의 근 발견 범위를 검증합니다. 자동 축소한 탐색 창, 계수 기반 범위 또는 변수별 지정 범위가 있으면 **실제로 적용한 범위**에만 해당합니다. 범위 밖의 해나 파라미터 경로 전체의 분기 동일성을 인증하지 않습니다. 슬라이더의 기준 곡선 배열은 변경하지 않습니다. 이전 파라미터의 검증 결과를 현재 결과처럼 재사용하지 않습니다.

## 첨부 코드의 수학적 판단

구간 산술·구간 자동미분으로 점 표본 사이의 숨은 근을 배제하자는 방향은 유효합니다. 다만 첨부 파일을 그대로 실행 경로에 넣으면 다음 문제가 있습니다.

| 첨부 구현·주장                                                        | 검토 결과와 처리                                                                                                                                                                    |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `captureConfidence = max(0.85, min(0.9999, 1-relativeUndecided*0.5))` | 확률분포·관측 모델·오차 상계가 없습니다. 검증한 길이가 0이어도 85%를 부여합니다. 설명에 나온 `M_req` 계산도 실제 코드에는 없습니다. 이 수치와 포획 신뢰도 UI는 채택하지 않았습니다. |
| 작은 미결정 길이 → 근 누락 확률이 작음                                | 성립하지 않습니다. 짧은 구간에 임의로 많은 근이 모일 수 있습니다. 검증한 **길이 비율**과 전체 검증 여부를 분리했습니다.                                                             |
| `abs(value)*8*EPSILON`으로 범위를 넓힘                                | 일반 초월함수의 엄밀한 오차 경계가 아닙니다. 인접 Float64 값으로 향하는 기본 연산과 해석적 나머지항을 사용합니다.                                                                   |
| `sinh`의 도함수를 `cosh(lo), cosh(hi)`만으로 계산                     | 0을 가로지르면 최솟값 1을 누락합니다. `tanh`의 도함수에도 같은 문제가 있습니다. 비단조 `cosh` 구간을 따로 계산합니다.                                                               |
| `f(lo)*f(hi)`로 부호 비교                                             | 곱이 언더플로하면 같은 부호를 다른 부호 또는 0으로 오인합니다. 일반 Float64 함수값의 부호도 증명의 근거가 아닙니다. 끝점 자체를 구간 평가해 부호를 확인합니다.                      |
| 인접 닫힌 구간의 근 개수를 단순 합산                                  | 공통 끝점의 같은 근을 두 번 셀 수 있습니다. 정확히 확인된 끝점 근은 점 구간으로 기록하고 중복 제거합니다. 단순히 인접한 두 근 구간을 합쳐 서로 다른 근을 없애지도 않습니다.         |
| `100.000%`와 미결정 구간 동시 표시                                    | 반올림으로 미해결 사실을 가릴 수 있습니다. 미결정 구간이 하나라도 있으면 **보류**, 길이 표시도 100% 미만으로 유지합니다.                                                            |
| Moore·Krawczyk 정리 언급                                              | 첨부 구현은 일반 다변수 Krawczyk 검증기가 아닙니다. 이번 구현도 단일 변수의 값 제외·단조성·구간 Newton 포함 판정으로 한정합니다.                                                    |

사잇값 정리가 근의 존재를, 엄밀한 단조성 또는 구간 Newton 포함 조건이 유일성을 뒷받침합니다. 구간 자동미분만 있으면 임의의 함수에 대해 유한 시간에 모든 근을 결정할 수 있다는 뜻은 아닙니다.

## 계산 모델과 반올림

검증 대상은 파서가 읽은 **유한한 Float64 상수·파라미터를 정확한 실수 계수로 고정한 수식**입니다. 사용자가 입력한 십진수가 실험값의 불확실성 구간이라는 뜻은 아닙니다. 내장 `pi`, `e`도 기존 계산기의 Float64 상수 의미를 유지합니다. 삼각함수의 범위 축소에 쓰는 수학적 π의 구간과 모델의 `pi` 상수는 구분합니다.

일반 솔버는 중간 연산도 Float64로 계산하지만 구간 검증은 그 계수로 정의한 실수 수식의 포함 관계를 다룹니다. 심한 상쇄·언더플로에서는 일반 솔버의 작은 잔차와 구간 검증 결과가 다를 수 있습니다. 검증 구간과 근의 소수 표시값의 오차 보장도 구분합니다.

- 기본 `+ - * /`는 IEEE-754 binary64 연산 결과의 바로 아래·위 표현값을 `DataView`로 구합니다. 0·비정규수·오버플로도 포함합니다. 정수 거듭제곱은 `Math.pow`의 오차를 가정하지 않고 구간 곱셈으로 계산합니다.
- `exp`: 인수를 정확한 2의 거듭제곱으로 나누어 `|z|≤1/8`로 축소합니다. 20차 Taylor 합에 첫 누락 항 절댓값의 두 배를 나머지 경계로 더하고 반복 제곱합니다. ±512 밖에서는 단조성으로 더 넓은 보수적 구간을 사용합니다.
- `ln`: 지수·가수를 비트로 분리하고 `t=(m-1)/(m+1)`의 양의 급수 `2Σ t^(2k+1)/(2k+1)`를 사용합니다. 32항 이후의 경계는 `2*t^65/(65*(1-t²))`입니다. 밑 10 로그의 배율도 같은 방법으로 감쌉니다.
- `sin/cos`: π의 알려진 인접 dyadic 경계로 사분면을 축소하고 Taylor 나머지 경계를 더합니다. 구간 내 극값도 포함합니다. 인수 절댓값이 10⁶을 넘으면 `[-1,1]`로 보수적으로 돌아갑니다. 그 안에 근이 없다고 추측하지 않습니다.
- `sinh/cosh/tanh`는 위 지수 구간·항등식·단조성을 사용합니다. `cosh`가 0에서 갖는 최솟값도 포함합니다.
- `sqrt`: `Math.sqrt`는 후보 생성에만 사용하고, 후보의 제곱과 입력값의 대소 관계를 정확한 BigInt dyadic 비교로 확인합니다. 확인 실패 시 넓은 경계로 돌아갑니다.

이는 형식 검증 도구로 프로그램 전체를 증명한 결과가 아닙니다. 위 수학적 포함 관계, IEEE-754 기본 연산·비트 표현, 지원 범위와 자원 한도를 전제로 한 구간 검증 구현입니다.

## 판정과 보류

1. 식이 구간 전체에서 정의되고 값 구간에 0이 없으면 해가 없습니다. 정의역에서 완전히 제외된 구간도 따로 기록합니다.
2. 전체에서 도함수가 0을 포함하지 않으면 끝점 구간의 부호로 해 부재·유일성을 판정합니다. 부호가 불명확하면 구간 Newton 상이 원래 구간의 내부에 엄밀히 포함되는지 확인합니다.
3. 결정하지 못하면 이분합니다. 중근·정의역 경계·극점·수치 해상도·미지원 연산·시간/작업 제한은 미결정 구간으로 남깁니다. Float64 함수값이 작다는 이유로 승인하지 않습니다.

미결정 구간 폭의 합은 위쪽으로, 전체 폭은 아래쪽으로 계산해 **검증한 길이 비율의 하한**을 구합니다. 이 비율에는 확인한 정의역 제외 영역도 포함됩니다. 미결정 목록과 독립적으로 완료를 판단하지 않습니다. 미결정 구간이 하나라도 남으면 완료가 아닙니다.

기본 한도는 6,000개 셀 평가, 분할 깊이 64, 약 250ms의 셀 사이 시간 검사, 유일근 구간 128개입니다. 중단한 모든 대기 구간도 미결정으로 돌려 누락하지 않습니다. 더 넓은 범위를 몰래 검증했다고 표시하지 않습니다.

## 남은 범위

- 일반 다변수 구간 Newton/Krawczyk 검증, 임의정밀도 검증, 모든 중근의 존재·중복도 인증은 없습니다.
- `asin/acos/atan`, 비정수 거듭제곱, 절댓값 1024를 넘는 정수 지수 등은 현재 구간 검증 미지원입니다. 일반 수치 솔버의 지원 여부와 별개입니다.
- `abs/min/max/floor/ceil/sign`은 값의 범위로 해 부재를 배제할 수 있지만 미분 가능한 단순근의 유일성 판정을 적용하지 않습니다. 구간 해의 정확한 경계도 인증하지 않습니다.
- 극점·열린 정의역 경계 바로 주변, 매우 가까운 근, 중근, 강한 상쇄에서는 작은 미결정 영역이 남을 수 있습니다. 예를 들어 `(x-2)^6=0`의 단일 근을 일반 솔버가 찾았어도 원래 6차 식의 구간 검증은 보류할 수 있습니다.

## 검증 기록

- 구간 연산·판정·통합 반례 35개를 포함한 단위·수치 회귀 검사 **449개 통과**, TypeScript·배포 빌드 통과.
- 고정 seed의 1,000개 함수 구간을 만들어 100자리 mpmath 계산과 비교했습니다. 정의역 검사가 허용한 구간의 끝점·중점에서 값·도함수 포함 관계 **5,580건**을 확인했고 위반은 없었습니다. 표본 대조 자체를 수학적 증명으로 대체하지 않습니다.
- 첨부 초월함수 `cos((3/pi)*x)-sinh(x)/3-0.95`는 `[-100,100]`의 유일근 구간 3개와 미결정 구간 0개를 확인합니다. 반데르발스 모델은 세 근 구간을 분리하면서 0의 극점 주변은 미결정으로 남깁니다.
- 첨부 문서의 7.5ms·6.0ms·99.99%는 이번 구현의 측정값 또는 보증으로 채택하지 않았습니다.

기존 브라우저 회귀 시나리오 62개가 통과했습니다. 새 구간 검증 시나리오 3개도 접이식 항목의 검사 선택자를 보정한 후 모두 통과했습니다. 설정의 저장·새로고침·끄기, 결과 캐시 갱신, 단순근·고차 중근·극점·해 부재의 구분, 번호 함수와 Markdown 다운로드를 확인했습니다. 전체 남은 문제는 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)에 유지합니다.
