## 실제 새 결함

`m=Number.MIN_VALUE=2⁻¹⁰⁷⁴`라 하면 정확한 실수 `m/2=2⁻¹⁰⁷⁵`는 **0과 m 사이**에 있습니다. Float64 끝점으로 이를 감싸려면 하한은 0 이하여야 합니다.

```ts
mul({ lo: Number.MIN_VALUE, hi: Number.MIN_VALUE }, { lo: 0.5, hi: 0.5 })
// 후보 반환: {lo: Number.MIN_VALUE, hi: Number.MIN_VALUE}

dyadicToInterval({ m: 1n, e: -1075 })
// 후보 반환: {lo: Number.MIN_VALUE, hi: Infinity}
```

두 결과 모두 실제 양의 실수 값을 제외합니다. 원인은 양수 곱의 하한과 `square` 하한을 `Number.MIN_VALUE`로 강제로 올리는 처리, 그리고 dyadic 변환에서 언더플로와 오버플로를 같은 분기로 처리하는 것입니다. 음수 곱에도 대칭 문제가 있습니다.

이는 단순한 느린 탐색 문제가 아니라 구간 포함성의 붕괴입니다. 이 구간으로 `0∉F(I)`를 검사하면 근 부재·완료를 잘못 승인할 가능성이 생깁니다. 실제 누락이 어떤 모델에서 얼마나 자주 발생하는지까지 측정한 결과는 아닙니다.

## 다음 수정본의 필수 조건

1. 실수 해석에서는 Float64 점 사이의 양수 실수를 제외하지 않습니다. 양의 언더플로에는 `[0, MIN_VALUE]`, 음의 언더플로에는 `[-MIN_VALUE, 0]`처럼 보수적인 포함 구간을 사용합니다. 단순 부호 보존과 실수 포함성은 별개입니다.
2. 정확한 dyadic→Float64 변환은 영점·양/음 언더플로·오버플로를 따로 처리해야 합니다. `addExactDyadic`가 지수 차이 4096을 넘으면 작은 항을 버리는 경로도 ‘정확’ 연산으로 쓰기 전에 보완해야 합니다. 이 경로는 코드 검토 사항이며 이번 11개 실행 게이트가 모두 검사한 것은 아닙니다.
3. 수정한 중심 다항식·인수 소거 인증도 위 구간 연산에 의존하므로 포함성 회귀가 먼저 통과해야 합니다. 고차 중근·도함수 영점만으로 원래 함수의 근을 확증하지 않는 기존 보호는 유지합니다.
4. Gaussian 지표는 명시한 하나의 상수 오프셋 확률 모델에 한정합니다. 임계점의 위치·높이를 점 근사로 계산한 값은 엄밀한 확률 상하한으로 표시하지 않습니다. 모든 해를 찾았을 확률과도 구분합니다.
