# 첨부 의견서 검토 기록

검토 대상은 사용자가 제공한 `polymath_audit_and_architecture_report.md`와 `modules.ts`입니다. 보고서의 분석·코드 조각·벤치마크를 검토 제안으로 취급하고 현재 구현 및 재현 사례와 비교했습니다. 사용자는 새 계산 모듈을 개발하지 말라고 명시했으므로, 첨부 파일의 신규 모듈 로드맵은 이번 구현 범위에 포함하지 않습니다.

기존 원본 코드 묶음의 기준 커밋은 `95e167c`입니다. 아래 기록은 검토 판단과 검증 결과를 구분하며, 첨부 보고서의 ‘패치 후’ 표를 이번 저장소에서 직접 수행한 검증으로 간주하지 않습니다.

## 기존 Equation Solver에 대한 판단

| 항목                               | 확인한 사항                                                                                                                                                                                                                                                                           | 반영 결과                                                                                                                                                                                      |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BUG-01 · 미지수 `f`와 조건식 충돌  | 근 정의보다 조건식 분류가 늦어 `f(min)`이 미지수 `min`의 근 정의로 읽힐 수 있었습니다.                                                                                                                                                                                                | 좌변 분류를 수정했습니다. `f^2=4`의 두 실근과 `f`를 사용하는 Colebrook 모델을 검증합니다.                                                                                                      |
| BUG-02 · 단항 부호와 거듭제곱      | 현재 파서의 재귀는 이미 `-2^2=-(2^2)`를 구현합니다. 보고서가 제시한 우선순위 불일치는 현재 코드에서 재현되지 않았습니다.                                                                                                                                                              | 정상 파서를 교체하지 않고 음수 밑·음수 지수·오른쪽 거듭제곱 결합 회귀를 추가했습니다.                                                                                                          |
| BUG-03 · 일반 등식의 보조식 추론   | 두 행 `k=4`와 `x^2=k`에서 `k`가 미지수인 것은 일반 등식 문법의 현재 의미입니다. 이를 자동 보조식으로 바꾸면 `x=2` 및 두 행 `x=y`와 `y=2`도 달라질 수 있습니다.                                                                                                                        | 자동 추론은 채택하지 않았습니다. UI 파라미터 또는 명시적 보조식 문법을 사용합니다. 기존 의미를 회귀로 확인합니다.                                                                              |
| BUG-04 · 0 근처·세제곱근 추적 중단 | `(x-a)*(x+a-2)=0`과 `x^3-(2-a)=0`에서 `a=2`의 정상 추적 실패가 재현되었습니다.                                                                                                                                                                                                        | 다항식 근 분리·원래 모델의 잔차 확인을 이용한 보정과 좁은 단일근 구간의 처리를 보완했습니다. 역방향 확인과 작은 근·극점·분기 소실·먼 주기 보호는 유지합니다.                                   |
| BUG-05 · 문법 일관성               | 선형의 괄호 암묵적 곱셈과 대문자 함수 호출은 개선할 수 있습니다. 반면 선형의 `e`, `pi`는 기존 식별자이며, `min(x,1)`은 조건식의 정확한 정규식과 일치하지 않습니다.                                                                                                                    | 호환 가능한 곱셈·함수 호출 개선을 적용했습니다. `e`를 쓰는 기존 선형 모델을 보존했습니다. `min(x,1)` 오분류는 재현되지 않았으며 별도로 발견한 `SIN(0)=x` 함수 행의 조건식 오인을 수정했습니다. |
| BUG-06 · CSV 형식                  | 메인 화면과 해별 패널의 셀 이스케이프·줄바꿈 방식이 달랐습니다. 현재 변수 이름에는 쉼표·개행을 허용하지 않아, 보고서의 이름 예시로 유효 입력 손상이 재현되는 것은 아닙니다. `SolvePayload.result`는 필수이며 기존 렌더링 조건도 있어, `undefined` 접근 주장은 별도 재현이 필요합니다. | 공통 CSV 셀 이스케이프와 CRLF 출력을 사용하도록 통일했습니다. 확인하지 않은 런타임 오류가 발생했다고 기록하지 않습니다.                                                                        |

일반 등식에서 상수를 분리하려면 UI에서 `k`를 파라미터로 등록하거나, 다음처럼 명시적 근 정의와 보조식을 각각 한 줄에 적습니다.

```text
k = 4
f(x) = x^2 - k
```

BUG-04는 부분 개선 상태입니다. 그래프 격자가 특이점을 포함하는 경우와 현재값 경로가 그 점을 건너는 경우가 달라, 추가 배포 확인에서 미해결 사례가 발견되었습니다. 해결 완료로 취급하지 않으며 [인계할 문제와 재현 절차](KNOWN_ISSUES.md)에 기록했습니다. 미검증 후속 패치는 실행 코드에 반영하지 않았습니다.

## UI·상태·성능 제안의 반영

- **초기 앵커 채택 후 재계산:** 첫 응답에서 곡선에 사용한 앵커를 함께 반환하고 UI가 같은 식별자·계산 입력을 채택하도록 바꿨습니다. 앵커 저장만을 이유로 동일 입력을 다시 풀지 않습니다.
- **공백을 포함한 근 정의 행 수:** `f( x )`와 조건식·함수 좌변을 구분하는 공통 입력 처리를 사용합니다. 파서는 허용하는데 화면에서는 0개로 세는 불일치를 보완했습니다.
- **휠 확대 경계:** 기존 `[-4,5]`도 중심은 0.5로 대칭입니다. 다만 최대 스팬 8보다 허용 범위 폭 9가 넓어 최대 축소 창의 위치가 하나로 정해지지 않았습니다. 최대 창을 `[-3.5,4.5]`로 일관되게 맞추고 경계에서 반복 확대·축소하는 사례를 추가했습니다. 이를 기존 범위의 단순 ‘비대칭’으로 설명하지 않습니다.
- **12차 초과 다항식:** 다항식 전용 경로의 제한을 넘으면 일반 수치 탐색의 유한 범위를 사용합니다. `x^13-200^13=0`의 근이 기본 탐색 범위 밖인 것은 현재 제한에 해당합니다. 차수 상수만 올려 모든 실근 탐색을 약속하지 않고, 범위 안내와 고급 범위 설정을 유지합니다.
- **슬라이더·전역 탐색:** 호환되는 고정 해의 현재값·곡선을 먼저 반환하고 전역 해 목록을 별도로 갱신합니다. 이때 과거 목록·범위를 현재 결과처럼 재사용하지 않고 갱신 대기임을 구분합니다. 중간 드래그 값의 전역 탐색은 생략하고 최신 입력의 해 목록을 갱신하는 요청 순서를 검증합니다.
- **입력 지연·자동 저장:** 수식 입력에는 160ms, 값 조작에는 16ms 요청 지연을 사용합니다. 저장은 300ms 유휴 시점으로 모으고 모드별 보류 초안 및 페이지 숨김·종료 시 저장 경로를 둡니다. 이 값은 스케줄링 설정이며 실제 응답 시간 보장이 아닙니다. 90% 개선, 특정 밀리초 응답, 메인 스레드 블로킹 ‘완전 제거’는 동일 조건에서 측정하지 않았으므로 주장하지 않습니다.
- **별도 사용자 UI 요청:** 시작 화면의 선택 카드 외 안내 문구와 왼쪽 분류 레일을 제거했습니다. 준비 중인 모듈은 계속 비활성으로 두며 기능을 새로 구현하지 않았습니다.

## 검증의 근거와 범위

수식 파서의 `f` 충돌·함수 호출·곱셈·연산 우선순위, 분기 추적의 해석해와 원래 수식 잔차, Worker의 요청 순서와 최신 해 목록, CSV 및 저장 동작을 관련 회귀 검증으로 확인합니다. 개별 예제의 통과를 모든 모델에 대한 완전 탐색·분기 동일성·성능 보장으로 확대하지 않습니다. 전체 검사 결과와 배포용 실행 검증은 이번 변경의 최종 작업 결과에서 보고합니다.

## 첨부 `modules.ts`를 편입하지 않은 이유

새 모듈 개발은 사용자가 보류했습니다. 파일도 현재 엔진에 복사하거나 UI·Worker에 연결하지 않았습니다. 다음 사항은 향후 해당 모듈을 요청받을 때의 검토 자료로만 남깁니다.

| 첨부 파일의 지점   | 실제 구현에서 확인한 사항                                                                                     | 향후 필요한 검토                                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ODE 보조식 평가    | ‘Topological sort’라는 주석과 달리 `helpers`를 입력 순서대로 실행합니다.                                      | 의존 관계 정렬, 순환·미정의 이름·중복 이름 검증이 필요합니다.                                                                                          |
| RK45 최소 스텝     | `errNorm <= 1`이 아니어도 `h <= minH`이면 결과를 승인합니다.                                                  | 최소 스텝 실패와 수렴을 구분하고 허용 오차 미달을 성공으로 표시하지 않아야 합니다. 절대·상대 오차, 유한성, 발산·강성·종점 처리를 별도 검증해야 합니다. |
| 다항식 회귀        | 입력 정규화는 있지만 실제 선형계는 정규방정식을 만든 뒤 가우스 소거로 풉니다. QR 구현은 없습니다.             | 데이터·차수·랭크 검증과 QR/SVD 비교, 원래 기저 계수 변환의 정밀도 검토가 필요합니다.                                                                   |
| 비선형 회귀·최적화 | 최대 반복에 도달해도 결과를 반환하며 명시적인 수렴 상태가 없습니다. 피벗·랭크 및 일부 입력 검증도 부족합니다. | 수렴·중단·실패 상태, 잔차·스텝 기준, 정의역, 경계에서의 수치 미분을 구분해야 합니다.                                                                   |
| 최상단 기능 목록   | BFGS, Simpson 3/8, cubic spline quadrature가 주석에는 있지만 파일의 구현으로 제공되지는 않습니다.             | 주석·문서·반환 API와 실제 구현 범위를 일치시켜야 합니다.                                                                                               |
| 공통 입력          | 일부 길이·조건 검사는 있지만 데이터·파라미터·설정 전체의 유한성과 허용 범위가 일관되게 검증되지는 않습니다.   | 기존 Equation Solver와 같은 안전한 입력·자원 한도·오류 처리 계약을 먼저 정의해야 합니다.                                                               |

새 모듈의 성능·정확도 표는 이번 작업의 직접 검증 결과로 사용하지 않습니다. 현재 적용할 기준은 [개발 시 고려할 기준](ENGINEERING_GUIDELINES.md)에 남깁니다.

## 2026-11-11 사용자 승인에 따른 지정 상수 UI 변경

과거 BUG-03의 일반 등식 해석을 엔진에서 일괄 교체하지 않습니다. 이번 사용자의 “모든 지정상수를 파라미터화” 요청에 따라 UI에서 다른 식에 실제 사용되는 유일한 숫자 정의를 Parameter로 자동 등록합니다. `k=4; x^2=k`에서 조절값은 k 정의를 대신하고 x를 풉니다. 단독 `x=2`와 기존 선형 e/pi 미지수는 보존합니다. 반복 정의는 조용히 덮어쓰지 않습니다. Remove는 값의 삭제가 아니라 조절 컨트롤 숨김입니다. 원본 소스와 값·범위·숨김·축 설정은 프로젝트에 보존합니다. 수식 축 변환은 표시 단계에서만 실행되며 원래 수치 해를 바꾸지 않습니다.
